# 094 · Fluxo assistido de conexão, verificação e variáveis de provedores

## Objetivo

Torna a configuração inicial e o diagnóstico dos quatro provedores (Claude, Codex, OpenCode e Gemini) claros e acionáveis dentro do Vokia: diferencia instalação de autenticação, oferece login assistido usando os fluxos nativos de cada CLI sem nunca guardar senhas no app, e permite configurar variáveis de ambiente/gateways opcionais por provedor.

## Já existe

- `desktop/src/features/providers/ProviderSetupDialog.vue` e `commands/providers.rs` verificam se o executável existe no `PATH` e descobrem modelos.
- `docs/vokia-visao-de-produto.md` seção 4 define o princípio: *"Nada de credenciais. O app nunca lê, guarda nem repassa logins. O usuário entra nas CLIs oficiais, e o app apenas as executa."*

## Comportamento

- **Diagnóstico em quatro estados claros (`check_provider_status_exec`)**:
  - `not_installed`: executável não encontrado no `PATH` nem em pastas conhecidas do sistema (`~/.local/bin`, `~/.npm-global/bin`, `~/.bun/bin`, etc.); exibe instrução curta de instalação.
  - `installed_signed_out`: CLI encontrada com versão válida, mas sem login/chave ativa; exibe botão **Conectar**.
  - `connected`: CLI verificada e autenticada (com versão e fonte exibidas: sistema ou caminho explícito).
  - `error`: erro legível e acionável (ex.: versão incompatível, `settings.json` ilegível, chave recusada com 401 vs. 403/VPN/plano inativo, banco OpenCode mais novo).
- **Fluxo assistido de login nativo por provedor (`start_provider_login_exec` / `submit_provider_login_code_exec` / `cancel_provider_login_exec`)**:
  - **Claude:** dispara `claude auth login` (browser/loopback) ou fluxo de código colado (`--claudeai`), enviando o código apenas pelo `stdin` da CLI e nunca para logs.
  - **Codex:** dispara browser login via `account/login/start` (quando `app-server` disponível) ou **device code** (`codex login --device-auth`), exibindo URL e código curto no diálogo.
  - **OpenCode:** funciona pronto em modo gratuito sem login; oferece campo opcional para chave **OpenCode Go** (guardada no cofre seguro do SO, nunca exposta ao frontend — apenas status `missing | saved | unreadable`) ou orientação para `opencode auth login`.
  - **Gemini (`antigravity`):** dispara login OAuth nativo (`acp authenticate` ou `agy acp --login` com código colado no Windows/headless) ou campo opcional de `GEMINI_API_KEY` no cofre do SO.
  - Ação **Desconectar** no menu do provedor roda o comando oficial de logout (`claude auth logout`, `codex logout`, ACP `logout` no Gemini), avisando quando a CLI compartilha o login do terminal do usuário.
- **Variáveis de ambiente opcionais por provedor**:
  - Seção *Ambiente* em `Configurações › Provedores` para configurar `BASE_URL` / gateways compatíveis (ex.: `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL`, `AGY_LLM_GATEWAY_URL`) e variáveis customizadas.
  - Bloqueia nomes reservados (`PATH`, `HOME`, `VOKIA_URL`, `VOKIA_TOKEN`, `VOKIA_CLI`).
  - Valores marcados como sensíveis ficam no armazenamento criptografado do SO (DPAPI no Windows / Keychain no macOS / Secret Service no Linux), retornando apenas `stored: true` nas leituras e sendo registrados no redator de logs.
- **Exposição MCP e CLI (`commands/dispatcher.rs`)**:
  - `check_provider_status` (`exposed`): devolve estado, versão e diagnóstico de cada provedor.
  - `list_provider_env` (`exposed`, sem valores sensíveis) e `set_provider_env` (`exposed` para variáveis não-sensíveis; login interativo com navegador marcado adequadamente).

## Estados e transições

- Provedor: `not_installed` → `installed_signed_out` → `connecting` (aguardando navegador/código) → `connected` | `error`.
- Cancelar login em andamento encerra o processo auxiliar da CLI e volta para `installed_signed_out`.

## Critérios de aceite

1. Dado uma CLI instalada no `PATH` mas não logada, quando `check_provider_status` executa, então reporta `installed_signed_out` (com versão) e o botão **Conectar** aparece no Setup e no seletor de modelos ([085](085.md)).
2. Dado o usuário clicando em **Conectar** no Codex em modo device code, quando o fluxo inicia, então o modal exibe o link e o código curto e muda automaticamente para `connected` ao concluir.
3. Dado uma chave OpenCode Go ou variável sensível salva, quando o usuário reabre as Configurações ou chama `list_provider_env`, então o valor real nunca retorna ao frontend nem aparece em logs — apenas `stored: true`.
4. Dado uma tentativa de cadastrar variável com nome reservado (`PATH` ou `VOKIA_TOKEN`), quando o usuário tenta salvar, então o backend rejeita com erro claro.
5. Dado um erro 403 no OpenCode Go com chave salva, quando o diagnóstico classifica o erro, então informa que a requisição foi recusada (plano inativo/rede) em vez de pedir para digitar outra chave como se fosse 401.
