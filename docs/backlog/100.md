# 100 · Grafo de Memória Bi-Temporal e Palácio Hierárquico

## Objetivo

Evoluir o grafo de memória do Vokia (`project_memories` + `memory_edges` + `ContextGraphPanel.vue`) para um **grafo de conhecimento bi-temporal e hierárquico**, combinando os modelos do **Zep/Graphiti** (validade temporal de fatos e arestas), **MemPalace** (organização espacial *Wings → Rooms → Drawers* com armazenamento local determinístico em SQLite) e **HippoRAG** (busca multi-hop ponderada no grafo), reduzindo contradições, alucinações e consumo de tokens.

## Já existe

- `desktop/src-tauri/src/db/learning.rs`: `project_memories`, `memory_edges`, `search_project_memories`.
- `desktop/src-tauri/src/commands/learning.rs`: `build_context_graph`, `query_memory_graph`, `save_memory_graph_fact`, `build_compact_memory_context`.
- `desktop/src/features/memory/`: `MemoriaPage.vue`, `ContextGraphPanel.vue`, `MemoryList.vue`.

## Comportamento

- **Validade bi-temporal em `project_memories` e `memory_edges`:**
  - Adicionar `valid_from`, `valid_until` (nullable) e `superseded_by` nas tabelas `project_memories` e `memory_edges`.
  - Fatos substituídos (ex.: assinatura de função refatorada, troca de biblioteca ou mudança de fluxo) são marcados com `valid_until` e ligados via `superseded_by`, deixando de entrar no contexto ativo sem perder auditoria histórica.
- **Hierarquia espacial (Palácio de Memória):**
  - Classificar memórias em `wing` (domínio/camada: `backend`, `frontend`, `orquestracao`, `ui`, `infra`), `room` (módulo/diretório, ex.: `orchestrator/adapters`) e `drawer` (fato específico ou decisão).
  - Na `MemoriaPage.vue`, permitir navegar/filtrar por `wing` e `room`, além de exibir nós de memória e arestas temporais no `ContextGraphPanel.vue`.
- **Recuperação multi-hop (estilo HippoRAG / Vesalius):**
  - Atualizar `query_memory_graph` para percorrer até 2 hops (`card ↔ file ↔ memory ↔ module`) ranqueando por: correspondência lexical/FTS5, proximidade no grafo (Personalized PageRank simplificado / peso das arestas), recência e `pinned`.
  - Retornar apenas os nós e fatos mais relevantes com caminhos de arquivo exatos para minimizar greps exploratórios dos agentes.

## Critérios de aceite

1. Dado um fato antigo sobre um arquivo e um novo fato conflitante salvo posteriormente para o mesmo escopo, quando `build_compact_memory_context` monta o prompt, então apenas o fato vigente (`valid_until IS NULL`) é injetado.
2. Dado um agente chamando `memory_graph_query` com o nome de uma feature ou arquivo, quando há conexões de 2 hops (`card → file → memory`), então a ferramenta retorna o mapa de arquivos e decisões ligadas sem precisar varrer o repositório inteiro.
3. Na `MemoriaPage.vue`, o usuário consegue filtrar por domínio (`wing`), módulo (`room`), agente e busca textual, além de inspecionar fatos históricos substituídos.

## Referências

- `haplollc/Vesalius` (mapeamento estrutural local de código e dependências via MCP).
- `MemPalace/mempalace` (*Method of Loci*: *Wings → Rooms → Drawers* + grafo temporal local).
- `getzep/graphiti` (grafo de conhecimento bi-temporal para agentes de IA).
- `HippoRAG` (indexação hipocampal + Personalized PageRank para recuperação multi-hop).
