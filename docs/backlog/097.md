# 097 · Pesquisa web unificada para provedores sem busca nativa

## Objetivo

Garante que agentes rodando em qualquer um dos quatro provedores (especialmente OpenCode e provedores customizados que não trazem busca web embutida) consigam pesquisar documentação e referências atualizadas na web, sem degradar o *prompt cache* nem a latência dos provedores que já possuem busca web nativa (Claude, Codex e Gemini).

## Já existe

- Claude Code, Codex CLI e Gemini/Antigravity possuem busca web nativa embutida nas próprias CLIs.
- OpenCode (especialmente com modelos gratuitos ou locais) e `GenericCli` não garantem busca web nativa.
- `docs/vokia-visao-de-produto.md` seção 8.2 já prevê a camada **Pesquisa** no fluxo de orquestração.

## Comportamento

- **Sinalização declarativa em `providers.rs`**:
  - Novo campo `has_native_web_search: bool` em `ProviderConfig` (padrão `true` para `claude`, `codex` e `antigravity`/`gemini`; `false` para `opencode` e `GenericCli`, ajustável pelo usuário).
  - **Regra baseada em benchmark (evitar quebra de cache):** provedores com `has_native_web_search == true` **não** recebem a ferramenta `web_search` do Vokia no prompt por padrão — continuam usando sua busca inline nativa (que reaproveita o *prompt cache* e responde ~2× mais rápido).
- **Ferramenta `web_search` para provedores sem busca nativa**:
  - Exposta via catálogo (`commands/dispatcher.rs` → `web_search`, acessível via MCP e `vokia-cli`) quando há backend de pesquisa configurado.
  - Suporta dois modos configuráveis em `Configurações › Pesquisa`:
    1. **Provedor auxiliar (Side-thread enxuta):** usa um provedor local já conectado que tenha busca nativa (ex.: Codex ou Gemini em turno efêmero *toolless*, sem skills nem contexto do repositório, limitado a pesquisar e devolver resumo curto com URLs fonte);
    2. **Conector MCP / API de busca dedicado:** delega para um servidor MCP de busca configurado pelo usuário (ex.: Brave Search, Exa, Tavily ou Context7 para documentação de bibliotecas).
  - Cada resposta retorna resumo objetivo + lista de URLs fonte verificáveis, dentro de um teto de caracteres para não poluir o contexto do agente chamador.
  - Respeita `step_labels.rs` ([090](090.md)) exibindo *"Pesquisando na web: «query»"* e registra a busca nos `[work steps]` ([091](091.md)).
- **Segurança e respeito a permissões**:
  - Respeita o nível de permissão do projeto (em projetos com acesso à rede bloqueado ou modo restrito configurado pelo usuário, exige aprovação na Barra de Ação ou bloqueia explicitamente).
  - Nunca tenta contornar CAPTCHAs ou barreiras anti-bot.

## Estados e transições

- Agente em provedor sem busca nativa chama `web_search(query)` → verifica configuração → executa via provedor auxiliar ou MCP configurado → devolve resumo + URLs | erro acionável (*"Nenhum provedor de pesquisa configurado em Configurações › Pesquisa"*).

## Critérios de aceite

1. Dado um agente rodando no Claude, Codex ou Gemini (`has_native_web_search = true`), quando abre sessão, então não paga tokens extras pela ferramenta `web_search` do Vokia e usa sua busca nativa.
2. Dado um agente rodando no OpenCode (`has_native_web_search = false`) com um provedor auxiliar conectado, quando chama `web_search` via MCP ou `vokia-cli`, então recebe uma resposta concisa com URLs fonte sem vazar arquivos do projeto na consulta.
3. Dado nenhum backend de pesquisa configurado, quando um agente chama `web_search`, então recebe erro claro explicando o que configurar, sem falhar silenciosamente.
4. Dado uma pesquisa executada, quando o usuário observa a Barra de Ação ou Conversas, então aparece o rótulo legível *"Pesquisando na web: «termo»"*.
