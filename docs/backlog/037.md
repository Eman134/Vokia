# 037 · Checkpoint por turno e desfazer

## Objetivo

Permite desfazer o que um agente fez num turno, sem recorrer ao git manual. Antes de cada turno o sistema guarda o estado do worktree, e o usuário volta a esse ponto pela conversa.

## Comportamento

- Antes de cada turno de agente num card com worktree, o sistema grava o estado dos arquivos numa ref oculta do git (`refs/vokia/<card>/<turno>`), incluindo alterações não commitadas.
- A conversa mostra, em cada mensagem de turno, a ação "Voltar para antes deste turno".
- Ao escolher, o sistema pede confirmação mostrando quantos arquivos serão restaurados.
- A restauração devolve os arquivos do worktree ao estado gravado. Mudanças feitas depois daquele ponto, por agentes ou pelo usuário, são descartadas.
- Não há restauração com um agente trabalhando no mesmo worktree: a ação fica desativada com o motivo.
- O diff de cada turno sai da comparação entre dois checkpoints seguidos.
- Os checkpoints de um card são apagados quando o worktree é removido.
- A restauração fica disponível como comando (`restore_checkpoint`) pelo MCP e pelo `vokia-cli`.

## Estados e transições

Não modelado no diagrama.

## Critérios de aceite

1. Dado um card com worktree, quando um agente começa um turno, então existe uma ref `refs/vokia/<card>/<turno>` com o estado anterior ao turno.
2. Dado um turno que alterou arquivos, quando o usuário escolhe "Voltar para antes deste turno" e confirma, então os arquivos voltam exatamente ao estado gravado, incluindo os não commitados.
3. Dado um agente trabalhando no worktree, quando o usuário abre a ação de voltar, então ela está desativada e mostra o motivo.
4. Dado um card concluído, quando o worktree é removido, então as refs de checkpoint do card deixam de existir.
5. Dado dois checkpoints seguidos, quando o usuário pede o diff do turno, então o diff mostra só o que mudou naquele turno.
