# 093 · Cliente ACP em Rust para OpenCode e Gemini com relay MCP local

## Objetivo

Implementa um cliente genérico do **Agent Client Protocol (ACP)** em Rust (`orchestrator/adapters/acp/`) com perfis (*flavors*) específicos para **OpenCode** (`opencode acp`) e **Gemini** (`antigravity acp` + opção de `@google/gemini-cli`), incluindo um relay HTTP local para servidores MCP stdio — elevando OpenCode e Gemini ao mesmo nível de primeira classe do Claude e do Codex.

## Já existe

- `orchestrator/adapters/opencode.rs` roda `opencode run --pure --format json` com `ToolTransport::VokiaCli` e recusa `PermissionLevel::Liberado` por falta de sandbox/aprovação equivalente.
- `orchestrator/adapters/antigravity.rs` roda `agy -p= --input-format stream-json --output-format stream-json` com `ToolTransport::VokiaCli`, aparecendo na interface como "Antigravity" em vez de "Gemini".
- `providers.rs` já declara `ProviderProtocol::OpenCodeJson` e `ProviderProtocol::AntigravityStream`.

## Comportamento

- **Cliente ACP unificado (`orchestrator/adapters/acp/`)**:
  - Gerencia transporte JSON-RPC/ACP sobre stdio, `initialize`, `session/new`, `session/load`, `session/resume`, `session/prompt`, `session/cancel`, `session/set_model`, `model/list`, streaming de texto/pensamento/ferramentas, eventos `plan` ([088](088.md)) e permissões via `PermissionGate` do Vokia.
  - Pool de sessões ociosas com retenção segura quando houver comando/subagente em background ativo (`workHold`, até 30 min sem atividade / 4 h máximo), preservando o `session_id` no SQLite.
- **Relay Streamable HTTP local para MCP (`mcp/stdio_relay.rs`)**:
  - Sobe cada servidor MCP configurado (e a ponte do próprio Vokia) em `http://127.0.0.1:<porta>/mcp/...` com token bearer efêmero por diretório/sessão.
  - Evita vazamento de processos MCP stdio no OpenCode 2.x (que mantém servidores por diretório após `session/close`) e garante que o MCP funcione mesmo em modo `Leitura`/sandbox sem quebrar como ocorria com o `VokiaCli`.
- **Flavor `opencode` (`opencode acp`)**:
  - Desativa ferramentas redundantes do OpenCode (`question`, `opencode_list_mcp_resources`, `opencode_read_mcp_resource`) via `OPENCODE_CONFIG` temporário sem sobrescrever `opencode.json` do projeto nem regras globais do usuário (economia ~11% de tokens/turno).
  - Suporta catálogo dinâmico com *relist* após 5 s (OpenCode 2.x atualiza catálogo em background) e ordenação destacando modelos **Grátis** (`opencode/big-pickle` etc.) sem exigir conta.
  - Suporta *steering* via extensão `_session/steering` (OpenCode 2.3+) com detecção de steers não lidos (`unreadSteers`) devolvidos à fila.
  - Recupera resultados de subagentes e comandos em background (`unsentBackgroundTurns`) observando `session/list` quando uma tool termina em status `"running"`.
  - Com controle de permissões pelo `PermissionGate` via ACP, passa a suportar todos os níveis de permissão (`Leitura`, `Edição` e `Liberado`).
- **Flavor `gemini` (`antigravity acp` e opção `gemini` CLI)**:
  - Renomeia o rótulo exibido do provedor `antigravity` para **Gemini** (mantendo `id: "antigravity"` ou alias retrocompatível em `providers.json` e perfis existentes para não quebrar instalações atuais).
  - Passa `--gemini-dir` como caminho absoluto e `--app-data-dir` relativo, preservando ordem de modelos retornada pela CLI (plano Pro/Ultra vs. Free vs. `GEMINI_API_KEY`).
  - Suporta *steering* por segundo `session/prompt` (CLI 1.5+), manutenção de turno aberto enquanto comando de background roda (`wakesAfterPromptEnds`) e rotação de sessão por handoff ([091](091.md)) quando o contexto se aproxima do limite.
  - Suporta opcionalmente usar `@google/gemini-cli` (`gemini`) como preset/variante para usuários que preferem a CLI direta com API key / Google Code Assist.
- **Compatibilidade com legado**:
  - Mantém os adaptadores antigos (`OpenCodeJson` / `AntigravityStream`) como fallback configurável enquanto versões antigas das CLIs ainda existirem em máquinas de usuários.

## Estados e transições

- Processo ACP: `parado` → `inicializando` → `conectado` → `em_turno` | `aguardando_background` | `ocioso` → `encerrado`.
- Erro de sessão perdida (`-32602` no OpenCode 2, `-32002` padrão ACP): recria sessão automaticamente injetando o pacote de handoff ([091](091.md)).

## Critérios de aceite

1. Dado o OpenCode 2.x instalado, quando um agente executa um turno via `opencode acp`, então recebe as ferramentas do Vokia pelo relay HTTP MCP local, funciona em modo `Leitura`, `Edição` e `Liberado`, e encerra o relay ao fechar a última sessão do diretório.
2. Dado um usuário sem conta OpenCode Go, quando descobre modelos do OpenCode via ACP, então lista e executa modelos gratuitos normalmente.
3. Dado o Antigravity CLI instalado, quando o usuário abre o Vokia, então vê o provedor rotulado como **Gemini**, executa turnos via `acp` com streaming, permissões no Vokia e preservação de sessões antigas.
4. Dado uma queda ou perda de `session_id` em uma sessão ACP, quando o próximo turno inicia, então o adaptador detecta o código de sessão ausente, abre nova sessão e injeta o handoff sem falhar silenciosamente.
5. Dado um agente OpenCode ou Gemini emitindo atualizações de plano via ACP, quando o evento chega, então alimenta o `TurnPlan` ([088](088.md)) e o `step_labels` ([090](090.md)).
6. Dado perfis de agentes já salvos com `cli: "antigravity"`, quando o Vokia atualiza, então continuam funcionando sem migração manual.
